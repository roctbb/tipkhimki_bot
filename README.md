# Бот новостей Химок

Принимает сообщения в личном чате, собирает их до паузы в 120 секунд и пересылает
каждому администратору. Поддерживает текст, фото, видео, голосовые, аудио, документы,
видеосообщения, анимации, стикеры, контакты и геопозиции. Альбомы отправляются отдельными
сообщениями. Администраторы могут блокировать пользователей и отвечать им через бота.

## Запуск через Docker Compose

1. Установите и запустите Docker с Compose.
2. Скопируйте настройки:

   ```sh
   cp .env.example .env
   chmod 600 .env
   ```

3. Заполните `BOT_TOKEN` и `ADMIN_IDS` в `.env`. Несколько ID разделяются запятыми.
   Каждый администратор должен сначала открыть личный чат с ботом и отправить `/start`.
   Если нужен прокси, задайте `PROXY_URL=socks5h://user:password@host:port`.
   Для символа `$` в значениях `.env` используйте одинарные кавычки вокруг значения,
   чтобы Compose не подставлял переменные. `config.py` в образ не включается.
4. Остановите прежний процесс бота. Запускайте только один экземпляр с этим токеном:

   ```sh
   docker compose up -d --build
   docker compose logs -f --tail=100 bot
   ```

Образ работает от непривилегированного пользователя. Порты открывать не нужно:
бот получает обновления через long polling. При остановке контейнер дожидается текущего
запроса, незавершённая очередь остаётся в базе. При наличии webhook его нужно отключить
перед переходом на polling; бот не удаляет webhook автоматически.

База `/app/data/bot.sqlite3` находится в постоянном томе `bot-data` и сохраняется при
`docker compose down`, пересборке и замене контейнера. **`docker compose down -v`
удаляет очередь, блокировки и привязки ответов.** Не используйте его при обновлении.
Не подключайте один том одновременно к нескольким экземплярам. Дополнительно бот
удерживает файловую блокировку базы от второго процесса.

Перенос старой версии: дождитесь отправки её накопленных сообщений перед остановкой —
они хранятся только в памяти и автоматически перенести их невозможно. Прежний исключённый
ID `7901962333` импортируется в блокировки только при первом создании базы. Его можно
убрать через `/unblock`; после рестарта блокировка не вернётся. Для новой базы без
начальных блокировок задайте `INITIAL_BLOCKED_IDS=`.

## Команды и ответы администратора

Команды управления работают только в личном чате и только для ID из `ADMIN_IDS`.

| Действие | Как выполнить |
| --- | --- |
| Заблокировать | `/block 123456789` |
| Разблокировать | `/unblock 123456789` |
| Список блокировок | `/blocked` |
| Состояние доставок | `/queue` |
| Последние 20 постоянных ошибок | `/failed` |
| Повторить доставку после исправления причины | `/retry 42`, где 42 — номер из `/failed` |
| Справка | `/help` |

Для ответа нажмите **«Ответить»** на пересланном ботом сообщении или карточке `User ID`
и отправьте текст либо вложение. Бот скопирует ответ пользователю от своего имени,
без ссылки на профиль администратора. После успешной отправки администратор получит
подтверждение. Связи ответов сохраняются при перезапуске и не зависят от настроек
приватности автора пересылки. Сообщения, пересланные прежней версией бота, таких связей
не имеют: отвечать нужно на новые сообщения. `/block` и `/unblock` также можно отправить
ответом на карточку или пересланное сообщение, без указания ID.

Блокировка отменяет все ожидающие доставки, благодарности и ответы этому пользователю.
Новые сообщения и команды заблокированного пользователя молча игнорируются.
Уже доставленные сообщения не удаляются. Разблокировка разрешает новые сообщения,
но не восстанавливает отменённую очередь. Администратора заблокировать нельзя.

## Как работает очередь

- SQLite хранит очередь, статусы каждой доставки, блокировки, связи для reply и позицию
  чтения Telegram. Изменения от входящего обновления и его номер фиксируются одной
  транзакцией. Повторно полученное обновление не создаёт вторую отправку.
- Обработка и отправка последовательны, без фонового потока и общей изменяемой очереди.
  После паузы пользователя пакет закрывается; новые сообщения образуют следующий пакет.
  Интервал polling добавляет до примерно 10 секунд при отсутствии нагрузки. Сеть и
  ограничения Telegram могут увеличить задержку.
- У каждого сообщения отдельная доставка каждому администратору. Сетевые ошибки и
  ошибки сервера повторяются с задержкой от 5 секунд до часа; для HTTP 429 используется
  `retry_after`. Успешная доставка одному администратору не повторяется из-за сбоя у другого.
  Порядок ожидающих сообщений одного пользователя одному администратору сохраняется.
- Постоянные ошибки (например, удалённое исходное сообщение или запрет отправки) остаются
  в `/failed`. После устранения причины их можно повторить через `/retry`.
  Благодарность пользователю ставится в очередь только после доставки всего пакета
  всем его адресатам. При частичном провале благодарности нет.
- При изменении `ADMIN_IDS` новые сообщения получают актуальный список адресатов;
  ожидающие пересылки удалённым администраторам отменяются. Новые администраторы не
  получают старую очередь автоматически.

Гарантия отправки — **at least once**: если Telegram принял отправку, но соединение
оборвалось до ответа или процесс завершился до фиксации результата в SQLite, при повторе
возможен дубликат. Bot API не предоставляет ключ идемпотентности для этих методов.
Очередь хранит ID исходных сообщений, а не архив вложений: удалённый или недоступный
источник Telegram может перестать пересылать. История и связи автоматически не очищаются;
следите за объёмом тома. Для резервной копии используйте SQLite backup API или остановите
бота и скопируйте весь каталог данных вместе с WAL-файлами.

Документация API: [pyTelegramBotAPI](https://pytba.readthedocs.io/en/latest/sync_version/index.html),
[Telegram Bot API](https://core.telegram.org/bots/api).

## Локальная разработка и проверки

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python khimki_bot.py
```

Локальный запуск читает переменные окружения, а при отсутствии `BOT_TOKEN` или
`ADMIN_IDS` использует прежний `config.py` (`token`, `admin_ids`, `proxy`). Файл `.env`
автоматически читает только Compose; при локальном запуске экспортируйте переменные
или используйте `config.py`. Бот откажется запускаться с пустым списком администраторов.
По умолчанию база создаётся в `data/bot.sqlite3`; путь меняется через `DATABASE_PATH`.
`BATCH_DELAY_SECONDS` задаёт паузу перед пересылкой, по умолчанию 120.

Тесты используют временную SQLite-базу и подменённый Telegram API, реальных сообщений
не отправляют. Код разделён на `settings.py` (настройки), `storage.py` (база),
`bot_service.py` (входящие сообщения), `delivery.py` (отправки) и `khimki_bot.py` (запуск).
